timing
MuJoCo 3.17, revision 2858b247. Each point is the geometric mean of three seed median latencies; whiskers span those medians. Each run uses 20 warmup calls followed by 100 synchronized public step calls. Only batches 1, 256 and 1024 were measured; lines connect measurements. Each public call advances two DMC control rounds, with task-specific physics substeps. Timing includes wrappers, full State/task outputs on CUDA, and input/output transfers; construction, reset, warmup, frames and history are excluded. Native batch uses up to eight EPYC 7532 threads and MJWarp uses an RTX 3090, measured in the same allocation. Sequential CPU uses one EPYC 7413 core in a separate allocation. The six-panel selection matches Ahi's DMC figure; the full 17-environment results are included below. Vertical scales are shared.

divergence_summary
MJWarp versus native CPU, revision 2858b247. Points show the largest absolute error across lanes, components, batches 1/256/1024 and three seeds, over calls 1–10 or 1–100. Each paired run starts from the same native checkpoint and uses the same seeded uniform random actions without resynchronization. Velocity differences are in each task's native coordinate units. Reward values are public step outputs. The reward axis is linear close to zero and logarithmic beyond 1e-8; zero values are plotted at zero. These are descriptive maxima, not acceptance thresholds. Larger batches also sample more trajectories.
