# OGBench GPU context residency — candidate, 2026-09-29

The original Cube fidelity path needed six GPU contexts for the measured three-configuration batch, but its cache held four. A fresh RTX 3090 profile measured 2,045 ms of 2,231 ms per batch in context reconstruction. Three warmed calls caused 18 context misses and 18 evictions. The fixed-eight-entry candidate was superseded without promotion.

The replacement is local to OGBench. It preserves the shader, State, RenderState, simulator, and pixel-composition algorithms. Contexts are keyed by CUDA device, compiled appearance configuration, resolution, and world capacity. The renderer enumerates the batch's required keys; eviction prefers contexts outside that working set. Cube leases both passes while their buffers are needed by composition. Actual eviction synchronizes outstanding GPU reads before releasing context-owned resources. EGL contexts are not released.

Retention is bounded by GPU allocation bytes per device. Array accounting traverses the Warp model/data/render buffers and Torch views, merging overlapping allocation spans. Each entry is charged the larger of that census and the observed CUDA allocation increase during construction, so graph/BVH allocations that are not exposed as arrays are also considered. Shared initialization allocations can make this conservative. Default retention is the smaller of one quarter of total device memory and half the free memory when the device budget is first initialized. `STABLE_ENVS_OGB_CONTEXT_CACHE_BYTES` overrides that budget in bytes for each device.

This is a retained-context budget, not a hard cap on the entire process, CUDA allocator pools, output images, or source renderer. Constructing an unseen context temporarily needs additional memory before its exact weight is known. Previously measured keys evict before reconstruction. If the complete working set cannot fit, unleased contexts can stream through the cache and `active_evictions` records that cost. If the currently leased passes cannot fit together, rendering raises a clear error suggesting smaller chunks/resolution or a larger budget. It never frees buffers still leased by the compositor to meet the budget.

Validation: 43 local tests passed; two optional tests skipped. Tests cover a six-context working set repeated 20 times, variable allocation sizes, inactive-before-active eviction, leases, insufficient budgets, over-budget streaming, device isolation, default/explicit budgets, and exception cleanup. Lint and compilation checks passed.

## Supplemental GPU correctness result

Job 6803878 completed on NVIDIA L40S, gpu3002, batch256, with an explicit 4 GiB context budget. Both original and candidate ran on the same allocation and saved States. All full-batch image hashes agreed, and the candidate produced zero warm misses or evictions. It retained 2,680,160,256 bytes (2.496 GiB) of accounted contexts within 4,294,967,296 bytes. Process GPU memory snapshots were 5,507 MiB original and 6,927 MiB candidate; this includes other renderer, allocator, and source resources beyond the retained-context budget.

For CPU image output, ours improved from 131.03 to 2,424.39 FPS (18.50x). The candidate's paired source GPU rendering was 2,116.99 FPS, giving 1.145x speedup. Mean normalized MSE remained 0.0004634628. CUDA image output was 3,126.84 versus paired source 2,059.17 FPS (1.518x). Raw timing SD, memory, and hashes are preserved in `semantic_recovery_evidence/cube_context_budget_20260929/supplemental/`. These supplemental L40S results are kept separate from the completed RTX 3090 measurements.

Job 6802707 completed successfully. Baseline/candidate output hashes agree at every tested batch, and warmed candidate calls have zero misses and evictions within the context budget. At batch 256 with CPU image output, original-cache throughput was 114.53 FPS and candidate throughput was 1,545.17 FPS (13.49x improvement).
